# Open Camera 앱 개선 계획 · 콘셉트 프리뷰와 LUT 비교 설계

작성일: 2026-10-05 (Asia/Seoul)

상태: **사용자 검토용 설계**. 전체 개선 로드맵과 첫 번째 하위 프로젝트의 설계를 기록한다. 아직 구현 계획 승인, 이미지 생성, LUT 동봉, 제품 코드 변경, push 또는 배포가 이루어진 상태가 아니다.

## 1. 목표와 사용자 의도

사용자는 필터 개수만 늘리기보다 LUMIX LUT처럼 선택할 이유가 있는 색감과 상용 빈티지·뷰티 카메라에 가까운 결과물 완성도를 원한다. 인물·음식·풍경뿐 아니라 다양한 콘셉트의 샘플로 필터 차이를 쉽게 확인하고, 좋은 설정을 실제 촬영과 재현상에서 재사용하려 한다.

성공 기준은 “기능이 추가됐다”가 아니라 다음과 같다.

- 같은 원본에서 필터의 차이가 실제로 보인다.
- 어떤 상황에 어울리는 색감인지 선택 전에 판단할 수 있다.
- 썸네일, 비교, 촬영, 편집, 저장이 서로 모순되지 않는다.
- 인물과 음식의 중요한 색을 불필요하게 망가뜨리지 않는다.
- 기존 필터, 레시피, 최근 촬영, 촬영 비율과 전면 카메라 복귀 동작을 보존한다.

기존 검은 카메라 화면, 보라색 선택 상태, 중앙 셔터와 촬영 우선의 구조는 유지한다. 이번 작업은 기존 디자인의 확장이며 앱 전체의 시각적 교체가 아니다. 영상 기능은 제외한다.

## 2. 검토한 접근과 선택

| 접근 | 장점 | 위험 | 판단 |
| --- | --- | --- | --- |
| 필터와 장식 효과를 먼저 대량 추가 | 목록이 빠르게 풍부해짐 | 비슷한 결과가 늘고 선택이 어려워짐 | 채택하지 않음 |
| 샘플·비교 기준을 만든 뒤 색감과 질감을 선별 | 개선을 눈으로 확인하고 품질 기준을 공유할 수 있음 | 자산 준비와 비교 검증이 선행됨 | **추천 방향** |
| 외형과 내비게이션을 전면 재설계 | 새로운 인상을 줄 수 있음 | 기존 촬영 흐름과 안정성에 큰 영향 | 이번 범위에서 제외 |

다음 세 축을 분리한다.

1. **프리뷰 콘셉트:** 어떤 원본 사진으로 비교할지.
2. **컬러 룩:** 어떤 LUT로 색을 바꿀지.
3. **카메라 질감:** 입자, 번짐, 노이즈, 인화 느낌을 얼마나 적용할지.

인물 샘플을 선택한다고 인물 필터가 자동 적용되지 않는다. 카페 샘플을 선택한다고 촬영 모드나 화이트밸런스가 바뀌지 않는다.

## 3. 현재 프로젝트에서 확인한 사실

- `src/components/thumbs.ts`: `/samples/sample1.png` 한 장을 로드하고 실제 LUT·FX를 적용해 128×128 썸네일을 생성한다. 단일 샘플 로더와 소스/필터 ID 중심의 캐시를 확장해야 한다.
- `src/components/FilterStrip.tsx`, `FilterSheet.tsx`: 기존 필터 선택·강도 조절·최근 사용·즐겨찾기·커스텀 LUT 흐름이 있다. 새 기능으로 재구현하지 않는다.
- `src/App.tsx`: `keepOriginal`과 `oc-keep-original` 설정이 있다. 최초 기본값은 꺼짐이고 기존 설정을 유지한다.
- `src/App.tsx`, `src/capture/composite.ts`: 촬영 원본은 필터·뷰티·날짜 적용 전의 브라우저 영상 프레임이다. 현재 선택한 비율과 전면 미러링은 반영되며 최대 크기 제한이 있다. 무크롭 센서 RAW나 카메라 앱의 원본 파일이 아니다.
- `src/capture/composite.ts`: 보관 원본은 현재 JPEG 품질 0.95로 인코딩한다. 픽셀 무손실 파일이라고 표현하지 않는다.
- `src/capture/types.ts`, `store.ts`, `reprocess.ts`: 결과물과 별개로 컷별 `originals`를 보관하고 다시 현상한다. 보관함은 IndexedDB에 최대 10개 기록, 합계 50 MiB를 유지한다. 용량·개수 초과 시 오래된 기록이 정리된다.
- 얼굴/피부 마스크, 뷰티 조절, 그레인·소프트·블룸·할레이션·먼지·빛샘·빈티지 열화, 레시피와 필름 패턴 재사용은 이미 구현돼 있다.
- `docs/lut-provenance.md`: LENEU 계열은 재배포 조건 미확인으로 번들에서 제거한 이력이 있다. 이번 개선에서 이름만 바꿔 재동봉하지 않는다.
- `/Users/sunghyuk/Downloads/CLASSIC to STD`에는 `CLASSIC CHROME.cube`, `CLASSIC Neg.cube` 두 파일이 있다. 둘 다 33³ 데이터 형식이지만 제작자·이용 조건·입력 색공간 설명은 확인되지 않았다. 폴더 이름만으로 변환 방향을 확정하지 않는다.

## 4. 원본 보관과 비교 정책

### 4.1 세 종류의 원본을 구분

| 종류 | 용도 | 보관 방식 |
| --- | --- | --- |
| 앱 샘플 원본 | 모든 필터의 동일 기준 | 보정 전 기준 원본과 출처 기록을 프로젝트 자산으로 보관 |
| 비교용 현재 장면 | 움직이지 않는 동일 장면의 A/B 비교 | 장면을 한 번 동결해 메모리에 보관. 비교 종료 시 해제하며 자동으로 보관함에 저장하지 않음 |
| 사용자의 촬영 원본 | 촬영 후 재현상과 다른 LUT 비교 | 기존 ‘원본 보관’ 옵션으로 컷별 저장. 결과물마다 같은 원본을 중복 생성하지 않는 방향으로 후속 개선 |

실시간 영상의 서로 다른 프레임을 A와 B에 사용하지 않는다. 이미 필터가 적용된 결과를 A의 원본으로 사용하지 않는다.

### 4.2 기본값과 동의

- 샘플 원본은 사용자 사진이 아니므로 앱에서 유지한다.
- ‘현재 장면 비교’는 메모리 동결만 하므로 원본 보관 옵션을 강제로 켜지 않는다.
- 장기적인 재현상이 필요한 사용자는 기존 원본 보관을 선택한다. 저장 용량을 설명하되 기존 기본값은 바꾸지 않는다.
- 원본을 보관하지 않은 과거 사진은 원본으로 복원할 수 없다. 원본 부재를 안내하고 원본 기반 비교를 비활성화한다.
- 사용자가 외부에서 불러온 이미지는 ‘불러온 사진’으로 표시한다. 파일이 촬영 원본인지 이미 보정된 결과인지는 앱이 보증하지 않는다.
- 사진이나 커스텀 LUT를 서버에 업로드하지 않는다.

## 5. 콘셉트 샘플 7종

첫 자산 팩은 **인물 / 음식 / 풍경 / 카페 / 거리 / 야간 / 실내** 7종으로 한다. ‘현재 장면’과 ‘불러온 사진’은 생성 샘플이 아닌 별도 소스 선택이다.

| ID | 이름 | 기준 이미지 구성 | 주요 판별 요소 |
| --- | --- | --- | --- |
| `portrait` | 인물 | 실존 인물이 아닌 성인, 자연광, 피부와 머리카락, 밝은 무채색 옷 | 피부·입술·머리카락·화이트밸런스 |
| `food` | 음식 | 흰 접시에 구운 음식, 붉고 초록인 채소, 중립적인 자연광 | 식재료 색·흰 접시·질감 |
| `landscape` | 풍경 | 나무, 파란 하늘, 물, 밝은 건물과 그늘 | 녹색·파란색·밝은 영역·명암 |
| `cafe` | 카페 | 나무 테이블, 커피, 유리, 창가 빛과 실내 그늘 | 갈색·중성색·창문 밝기·실내 분위기 |
| `street` | 거리 | 흐린 낮의 거리, 무채색 외벽, 일부 색 있는 물체, 깊이감 | 대비·빨강·회색·일상 스냅 |
| `night` | 야간 | 작은 조명과 반사, 어두운 벽, 읽을 수 있는 그림자 | 빛 번짐·암부 색·노이즈·색 분리 |
| `interior` | 실내 | 흰 벽, 천, 목재, 따뜻한 조명과 창가 빛 | 혼합 조명·흰색·따뜻함·그림자 |

야간·실내는 해당 장면의 조명 특성을 포함하되, 필름 룩이나 과장된 컬러 그레이딩을 이미지에 미리 넣지 않는다. 흑백·바랜 필름·CCD는 샘플 소스가 아니라 룩으로 선택한다.

### 5.1 자산 제작과 기록

- 샘플은 정사각형이며 제품용 버전은 512×512로 제공한다.
- 생성 원본은 도구가 제공하는 해상도로 보관하고, 이후 확대 비교에 사용할 수 있는 1024 이상 기준 원본을 확보한다. 512 이미지를 단순 확대해 고해상도 원본으로 부르지 않는다.
- 색 비교의 기준 원본은 PNG 등 추가 손실 없는 형태로 보관한다. 제품 썸네일 소스는 변환 후 색 차이를 확인한 512 WebP를 사용한다.
- 샘플마다 생성 프롬프트, 도구, 생성일, 원본 경로, 변환 조건, 파일 해시와 자산 버전을 기록한다.
- 사용자가 제안한 `gpt-6-luna` / `high`는 프롬프트 정리·후보 평가에 사용하는 선호로 기록한다. 실제 래스터 생성은 이미지 생성 도구로 수행하며 언어 모델이 이미지 파일을 직접 생성한다고 전제하지 않는다.
- 실존 연예인, 상표·로고·워터마크, 의도적 필름 룩, 과도한 HDR, 플라스틱 같은 피부, 지나치게 얕은 심도는 피한다.
- 7종 각각을 독립적인 파일로 만든다. 한 장의 모음 이미지를 잘라 사용하는 방식은 피한다.

### 5.2 프롬프트 방향

공통: photorealistic reference photograph, square composition, neutral color rendering, visible natural texture, no filter, no vintage grading, no watermark, no logo, no readable text, preserve useful highlight and shadow detail. 주요 피사체는 중앙 안전 영역에 배치한다.

- 인물: fictional adult portrait, soft window daylight, natural skin texture, neutral clothing and background, realistic hair detail, restrained depth of field, no beauty retouching.
- 음식: a white ceramic plate with grilled food, red and green vegetables, rice, soft daylight, accurate appetizing colors, visible food texture, no stylized warm grading.
- 풍경: green foliage, blue sky, calm water, pale architecture and shaded areas, balanced daylight, realistic colors, no dramatic cinematic grading.
- 카페: coffee and clear glass on a wooden table near a window, balanced window highlights and indoor shadows, natural browns, no nostalgic filter.
- 거리: an everyday urban street under overcast daylight, gray facades and a few colored objects, realistic textures and depth, no brand signage, no teal-orange grading.
- 야간: a realistic evening scene with small lamps, reflections and readable dark surfaces, preserved light sources, restrained saturation, no added bloom or grain.
- 실내: white wall, fabric and wood under mixed window daylight and warm indoor light, natural material colors, visible tonal detail, no artificial color cast added in post.

AI 샘플은 선택을 돕는 데모이며 실제 카메라 품질을 증명하는 테스트 자료를 대체하지 않는다. 다양한 피부색과 어려운 조명은 별도 실제 사진 검증 세트에 포함한다.

## 6. 첫 번째 하위 프로젝트: 콘셉트 프리뷰와 원본 기반 LUT A/B

첫 구현의 범위는 7종 샘플 선택, 썸네일 소스 확장, 동일 원본 기반의 두 LUT 비교다. 뷰티 엔진 개편·새 빈티지 룩·정밀 LUT 포맷 변경·보관함 확장은 동시에 구현하지 않는다.

### 6.1 화면 흐름

1. 기존 ‘필터 전체 보기’를 연다.
2. 헤더 아래 ‘샘플: 인물’ 소스 선택을 연다.
3. 7종 중 하나를 고르면 스트립과 전체 필터 화면의 샘플이 함께 바뀐다. 실제 촬영 영상과 선택 LUT는 유지한다.
4. 비교 버튼에서 A와 B 필터를 선택한다. 기본 A는 현재 필터, B는 ORIGINAL이다.
5. 같은 원본을 고정한 비교 화면에서 `원본 / A / B`를 번갈아 확대해서 보거나 A/B를 나란히 본다.
6. ‘A 적용’ 또는 ‘B 적용’으로 선택을 확정한다. 닫기·취소는 현재 촬영 설정을 변경하지 않는다.

카메라 소스의 ‘현재 장면’은 선택한 순간 한 번 동결한다. ‘장면 새로고침’만 새 프레임을 가져온다. 편집 모드 기본 소스는 실제 편집 입력 사진이며 샘플 선택이 편집 원본을 교체하지 않는다.

비교용 소스의 선택은 현재 세션에서 유지한다. 샘플 ID는 로컬 설정으로 기억할 수 있지만 카메라 스냅샷·불러온 사진은 메모리에서만 관리한다. 새로 열었을 때 준비되지 않은 개인 소스를 과거 샘플과 혼동하지 않는다.

### 6.2 비교 규칙

- 첫 버전은 **LUT 색감 비교**다. 기본 파라미터를 공통으로 사용하고 뷰티·날짜·렌즈·입자·빛샘·필름 패턴은 끈다. 화면에 ‘색감만 비교’라고 표시한다.
- A/B 강도는 각각 0~100%로 조절하며 기본값은 100%다. 비교를 취소하면 앱의 기존 강도는 유지한다. 명시적 적용 때 선택 LUT와 해당 강도만 변경한다.
- ORIGINAL과 강도 0%는 동일한 비교 소스를 보여준다. 비교에서 쓰는 ‘원본’은 필터를 거치지 않은 해당 소스이지 센서 RAW가 아니다.
- 동일한 크롭·미러링·출력 크기·확대 배율을 사용한다. 한쪽만 더 확대된 비교를 만들지 않는다.
- 작은 모바일에서는 한 장을 크게 보는 원본/A/B 전환이 기본이다. 두 장 나란히 보기는 선택 사항이다. 데스크톱은 나란히 보기를 기본으로 할 수 있다.
- 비교용 미리보기의 긴 변은 최대 1024로 제한한다. 확대는 미리보기 픽셀 확대이며 원본보다 더 높은 디테일을 만들어낸다고 표현하지 않는다.
- 일반 썸네일은 해당 프리셋의 실제 LUT·기존 FX를 보여주는 흐름을 유지한다. 색감만 비교 화면과 다를 수 있음을 설명한다. 전체 룩 비교와 저장 단계의 축소·압축 재현은 후속 프로젝트로 분리한다.
- 커스텀 LUT도 같은 비교 엔진으로 처리한다. 등록된 LUT를 찾을 수 없으면 오류를 표시하고 원본을 필터 결과처럼 보여주지 않는다.

### 6.3 데이터 흐름과 책임

```text
7종 보정 전 샘플 / 동결 카메라 장면 / 편집 입력 / 보관한 컷 원본
                           ↓
              동일 소스 + sourceKey + 자산 버전
                           ↓
          공통 렌더러 → LUT A / LUT B / 원본
                           ↓
       취소: 기존 설정 유지 / 적용: LUT와 강도만 변경
```

예정 파일 경계:

- `src/preview/samples.ts`: 샘플 ID·라벨·경로·버전 목록과 샘플별 비동기 로딩. 단일 `getSampleImage()` 호출의 기본 동작은 호환 어댑터로 보존한다.
- `src/preview/source.ts`: 비교용 동결 소스, 식별 키, 크기와 명시적 해제 책임. 현재 카메라 스트림 자체를 보유하거나 재시작하지 않는다.
- `src/preview/compare.ts`: 동일 원본에 두 LUT를 적용하는 색감 전용 렌더링. 캔버스·비트맵·GPU 자원을 순차적으로 관리하고 이전 요청은 취소/무효화한다.
- `src/components/PreviewSourcePicker.tsx`: 콘셉트와 현재 장면 선택, 로딩·실패·새로고침 상태.
- `src/components/LutComparison.tsx`: A/B 선택, 강도, 원본 보기, 적용·취소와 포커스 관리.
- `src/components/thumbs.ts`: 샘플별 캐시, 자산 버전 반영, 취소된 작업의 출력 방지, 보이는 항목 우선 처리. 썸네일 크기는 우선 기존 128×128을 유지한다.
- `src/components/FilterSheet.tsx`, `FilterStrip.tsx`, `src/App.tsx`: 기존 선택·원본·커스텀 LUT를 연결한다. 새로운 책임은 모듈로 분리하며 App의 무관한 부분을 재작성하지 않는다.
- `src/styles.css`: 기존 검은 화면·보라색 선택·시트 토큰 안에서 소스 선택과 비교 화면만 확장한다.
- `docs/sample-provenance.md`, `public/samples/`: 실제 생성과 검증을 마친 샘플만 등록한다. 기존 `sample1.png`를 검증 전에 삭제하지 않는다.

썸네일 캐시는 소스/자산 버전, LUT ID, LUT 변경 버전, 강도와 FX를 식별할 수 있어야 한다. 캐시 결과는 최대 256개로 제한하고 최근 사용 순으로 정리한다. 대량 LUT·빠른 샘플 전환은 순차 처리하며 취소된 옛 작업이 최신 화면을 덮지 않는다. 실패한 이미지 로딩은 재시도를 막는 rejected Promise로 영구 캐시하지 않는다.

### 6.4 예외·접근성·호환성

- 이미지 로딩 실패: 오류와 다시 시도 제공. 다른 샘플로 조용히 바꾸지 않음.
- 카메라 미준비: 현재 장면 선택을 비활성화하고 샘플 선택은 계속 제공.
- 원본 부재: 최근 사진에서 원본 비교를 비활성화. 결과물을 원본으로 재사용하지 않음.
- LUT 삭제·로드 실패: 해당 비교 슬롯에 오류 표시, 적용 차단.
- 저장소 제한: 샘플 기본값으로 동작하고 세션 내 선택 유지. 사진 저장 성공을 거짓으로 표시하지 않음.
- 닫기·Escape·빠른 샘플 변경: 이전 렌더 결과를 무효화하고 자원 해제.
- 비교·샘플 선택 중 촬영 진행 상황, 네컷 원본과 필름 패턴을 변경하지 않음.
- 시트 포커스 트랩, Escape 닫기, 원래 버튼으로 포커스 복귀, 스크린리더용 선택·로딩·오류 상태 제공.
- 320×568, 390×844, 844×390, 1280×800에서 닫기·적용 버튼에 접근 가능. 가로 화면과 확대 글자에서도 사진 비교가 조작 버튼을 밀어내지 않음.
- 샘플 전환·비교 열기가 카메라 `getUserMedia`를 다시 호출하거나 촬영 프레임 중앙 정렬을 변경하지 않음.

## 7. 후속 개선 로드맵

각 단계는 독립적인 설계 → 구현 계획 → 구현·검증으로 진행한다. 아래 항목은 전체 방향이며 1단계의 구현 승인에 자동으로 포함되지 않는다.

### 단계 1 — 프리뷰와 비교 기준

- [ ] 7종 보정 전 샘플 제작·출처 기록.
- [ ] 샘플 전환·제한된 썸네일 캐시·같은 원본의 LUT A/B.
- [ ] 현재 장면 동결과 원본 보관의 차이를 명확하게 설명.
- [ ] 실제 촬영 사진 검증 세트로 필터 선정 기준 확보.

### 단계 2 — 가치 있는 컬러 룩

- [ ] CC0 또는 앱 동봉 권한을 확인한 후보 10~15개를 평가하고 실제로 구분되는 6~8개 이하를 선정.
- [ ] 각 LUT의 출처·원본 파일명·이용 조건·해시·입력 색공간·변환 방향·권장 강도 기록.
- [ ] 지정된 CLASSIC 두 파일은 먼저 기존 ‘내 LUT’ 경로에서 시험. 공개 동봉 허가 확인 전 `public/luts`나 공개 Git에 복사하지 않음.
- [ ] 입력 프로파일과 DOMAIN 처리 개선을 별도 호환성 설계로 진행. 기존 LUT 렌더 결과를 무단으로 변경하지 않음.
- [ ] 표시 이름과 내부 ID 분리. 기존 레시피·즐겨찾기 ID 유지.
- [ ] 인물·음식·풍경·카페·거리·야간에 적합한 추천 컬렉션을 기존 그룹 위의 탐색 기능으로 추가. 기존 전체 목록은 계속 접근 가능.

### 단계 3 — 구별되는 빈티지와 자연스러운 인물

- [ ] 기존 스튜디오·빈티지 프리셋을 먼저 평가. 비슷한 신규 프리셋을 중복으로 만들지 않음.
- [ ] 일상 35mm, 바랜 컬러, 즉석사진, 야간 CCD, 거친 흑백의 대표 룩을 선정. 기존 프리셋을 개선하려면 기존 ID에 조용히 덮어쓰지 않고 버전/새 옵션을 명시.
- [ ] 입자의 해상도 일관성, 암부 노이즈와 필름 입자 구분, 밝은 경계 주변의 번짐을 검증.
- [ ] ‘색감 / 질감 / 빛번짐’을 구분하고 기존 ‘전체 룩’·필름 우연성과의 중복 관계를 정리.
- [ ] 기존 피부 마스크·뷰티 기능의 피부 결 유지, 피부색 안정성, 움직임 중 일관성을 개선. 얼굴형 변형은 선택 사항으로 유지.
- [ ] 약한 뷰티와 검증된 룩을 묶은 인물 레시피 제공. 피부색별 실제 사진 검증 포함.
- [ ] 전체 룩 비교에서 저장 단계의 열화까지 반영하는 별도 미리보기 제공. 가능한 범위와 처리 시간이 명확해야 함.

### 단계 4 — 스튜디오와 재사용

- [ ] 동일 사진의 후보 2~4개 비교로 확장하되 모바일에서 작은 사진 네 장만 강제하지 않음.
- [ ] 기존 레시피의 복제·내보내기·가져오기. 버전 검증과 누락 LUT 안내 포함.
- [ ] 여러 장 불러와 같은 레시피 적용. 순차 처리·진행률·취소·개별 실패 복구 포함.
- [ ] 최근 촬영의 원본 다운로드·설정 백업·보관 용량 표시·정리 안내. 장기 보관함과 최근 10장 캐시를 구분.
- [ ] 현재 크롭된 원본의 한계를 유지·설명하거나, 무크롭 소스와 크롭 메타데이터를 함께 보관하는 별도 마이그레이션 설계. 기존 데이터에 없는 영역을 복원한다고 표현하지 않음.
- [ ] 즉석사진의 위치·여백·문구 편집을 실제 사진 중심으로 개선. 현재 템플릿과 네컷/하프프레임 동작 보존.

## 8. 품질 검증과 완료 기준

### 첫 단계 자동 검증

- 샘플 ID와 자산 버전, 로드 실패 재시도, 캐시 한도 256개 테스트.
- 같은 소스에서 ORIGINAL과 LUT 강도 0%가 같은 픽셀 결과인지 검증.
- A/B가 같은 크롭·미러링·확대 기준을 사용하고 서로 다른 영상 프레임을 읽지 않는지 검증.
- 빠른 샘플 전환, LUT 로드 중 닫기, LUT 삭제에서 오래된 결과가 최신 화면에 남지 않는지 검증.
- 비교 취소가 기존 필터·강도·뷰티·날짜·렌즈·필름 패턴·레시피를 변경하지 않는지 검증.
- 명시적 적용은 선택 LUT와 강도만 변경하는지 검증.
- 원본 미보관 기록은 비교 불가 안내, 저장소 차단은 세션 동작 유지 테스트.
- 기존 필터 선택·즐겨찾기·편집 사진 썸네일·StudioFramePreview 기본 샘플 호출의 호환성 검증.
- `npm run typecheck`, `npm run build`, 새 Playwright 테스트와 기존 전체 `npm test` 통과 확인.

### 실제 사진과 화면 검증

- 최소 21장의 실제 사진: 7종 장면마다 3장. 인물 검증은 다양한 피부색, 역광과 실내 조명을 포함한다.
- 같은 사진에서 기존 대표 필터와 새 후보의 차이를 나란히 기록한다. 차이가 거의 없는 후보는 수량을 채우려고 추가하지 않는다.
- 피부·음식·중성 회색, 밝은 영역과 그림자의 색·계조 붕괴를 확인한다.
- 작은 썸네일만 보지 않고 큰 이미지와 100% 픽셀에서 질감·밴딩·압축을 확인한다.
- 4개 화면 크기를 한 번에 점검하고 결함을 묶어서 수정한 뒤 최대 한 번의 확인 점검을 한다.
- 브라우저 자동 테스트는 실제 iPhone Safari/PWA의 카메라 복귀 동작을 증명하지 않는다. 전면 광각·백그라운드 복귀·중앙 정렬은 기존 임시 HTTPS에서 실제 기기 확인을 별도 기록한다.

## 9. 자산·라이선스 기준과 근거

무료 다운로드, 개인 보유, 사진 결과물의 상업적 사용, 앱에 원본 LUT 동봉·재배포는 구분한다. 이름 변경이나 수치 조정으로 재배포 권한이 생긴다고 전제하지 않는다. CC0 자산도 출처와 권리 고지 증거를 남긴다.

- [FreshLUTs 이용 조건](https://freshluts.com/termsandconditions): LUT에 CC0를 명시하며 권리 비침해를 보증하지는 않는다. 개별 업로더·출처 확인이 필요하다.
- [OpenShot LUT 출처 목록](https://github.com/OpenShot/openshot-qt/blob/develop/src/colors/AUTHORS.md): 수록 LUT의 원본·제작자·CC0 고지를 기록한 후보 목록. 이 앱에서의 시각적 품질 인증은 아니다.
- [IWLTBAP 이용 조건](https://luts.iwltbap.com/terms-of-sale.html): 사진·영상 작업 허용과 앱 포함·변형 재배포 제한의 구분 사례.
- [VSCO Film X](https://support.vsco.co/en/articles/12698496-vsco-membership-how-to-use-film-x): Strength·Character·Warmth를 분리한 룩 조절 참고.
- [Dazz 공식 소개](https://apps.apple.com/us/app/dazz-cam-vintage-camera/id1422471180): 카메라 계열별 색·질감과 원본 재처리의 제품 방향 참고.

상용 앱 관련 내용은 공식 설명을 조사한 것이며 동일 장면의 실촬영 비교 결과가 아니다. 새로운 LUT 동봉 시점에는 다운로드한 개별 파일과 이용 조건을 다시 확인한다.
