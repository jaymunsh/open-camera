# Open Camera · 대표 필름과 질감 품질 개선 설계

작성일: 2026-10-05 · Asia/Seoul

상태: 사용자 대화상 방향 승인, **이 설계서 검토 대기**. 구현 계획·제품 코드·신규 이미지 자산은 아직 작성하지 않았다. 문서 확인 후 상세 구현 계획을 작성하고 실행 방식을 확인한다.

## 1. 의도와 기준점

사용자는 필터 수보다 선택할 가치가 있는 색감, 아날로그 질감, 깔끔한 스튜디오, 설정 재사용을 원한다. 영상은 제외하며 기존 필터와 촬영 흐름을 유지한다. ‘상용적으로’는 이번 범위에서 결과물과 제품 완성도를 뜻한다. 결제·계정·클라우드 서비스는 추가하지 않는다.

현재 제품 코드와 자산을 `a1d152f`로 체크포인트 커밋했다. 직전 확인 결과는 타입 검사 통과, production build 통과, 최근 추가 기능의 Playwright 28개 통과(2.1분, 2 workers)다. 전체 246개 테스트를 이번 체크포인트에서 다시 돌렸다는 뜻은 아니다. 새 서버·터널, git push, 정식 배포는 하지 않았다. 임시 진단과 스크린샷은 삭제하지 않고 커밋 밖에 남겼다.

기존 `2026-10-05-camera-quality-roadmap-design.md`는 이전 단계의 설계 기록이다. 샘플 7종·동일 원본 LUT 비교·필름 컬렉션·제공 LUT 2종·Studio 취소·설정 요약은 현재 구현돼 있으므로 다시 만드는 대상으로 취급하지 않는다.

## 2. 접근 선택

| 접근 | 적용 범위 | 고려점 |
| --- | --- | --- |
| 필터 후보만 추가 | LUT 목록 | 선택지는 늘지만 입자·저장 결과의 차이는 해결하지 못함 |
| 기존 공통 셰이더를 전면 교체 | 모든 사진·프리셋·재현상 | 과거 결과까지 달라지는 호환성 부담이 큼 |
| **새 필름 모델을 선택적으로 추가** | 새 룩과 명시적 질감 선택 | 기존 결과를 보존하면서 비교·조정·저장 경로를 연결할 수 있음 |

세 번째 접근을 선택한다. App 전체나 카메라 시작·복귀 코드를 재작성하지 않는다. renderer와 설정 계약만 필요한 범위에서 확장한다.

## 3. 전체 로드맵과 이번 작업 경계

1. **1A — 필름 품질 기반:** 선택형 새 입자·광원 번짐 모델, 대표 룩 후보 최대 6종, 설정 저장·취소·재현상·썸네일 연결. 이번 상세 설계 범위다.
2. **1B — 자연스러운 인물:** 피부색 보호와 자연스러운 뷰티 조합. 1A 이후 별도 설계한다. 얼굴 마스크가 없는 사진 편집·재현상에서도 일관된 결과를 내는 것이 선행 조건이다.
3. **2 — 내 카메라와 일괄 처리:** 기존 레시피를 확장해 촬영 모드·프레임·문구까지 선택적으로 저장, 복제·백업·가져오기, 여러 사진 순차 처리. 별도 데이터 계약과 구현 계획이 필요하다.
4. **3A — 사진으로 만드는 스튜디오:** 불러온 사진으로 네컷·스트립·엽서 제작, 칸별 크롭·교체·순서, 편집 작업 저장. 기존 실시간 촬영과 분리한다.
5. **3B — 필름롤:** 프로젝트별 사진 묶음, 컨택트 시트, 백업·용량 안내. 최근 촬영의 10개/50 MiB 캐시를 장기 앨범으로 이름만 바꾸지 않는다.

각 하위 프로젝트는 별도로 설계·계획·검증한다. 이 문서 승인은 다른 단계의 구현이나 정식 배포 승인을 포함하지 않는다. 다인물 개별 보정, 생성형 AI, 동영상, 프린터 직접 연결, 계정·결제는 이번 범위 밖이다.

## 4. 1A 성공 기준

- 같은 원본으로 기존과 새 결과를 큰 이미지에서 비교할 수 있다.
- 단순 RGB 잡음 강도 변경과 구별되는 입자 크기·색·명암 분포를 제공한다.
- 광원 주변의 번짐과 사진 전체의 소프트 효과를 구분한다.
- 선택하지 않으면 기존 LUT·렌더 모델·기본값이 그대로 유지된다.
- 새 설정이 실시간·썸네일·촬영 저장·불러온 사진·원본 재현상에서 빠지거나 중복 적용되지 않는다.
- 기존 저장 사진과 레시피는 자동 변환하지 않으며, 원본이나 결과 파일을 덮어쓰지 않는다.

## 5. 대표 룩 후보

아래 6종을 비교 대상으로 만든다. 수량을 채우기 위한 출시 기준은 없다. 평가를 통과한 후보만 대표 컬렉션에 노출한다. 6개 미만이면 탈락 이유와 비교 결과를 남긴다.

| 역할 / 새 ID | 색감 목표 | 질감 목표 | 우선 평가할 기존 색 데이터 |
| --- | --- | --- | --- |
| 인물 / `signature-portrait-v1` | 피부·흰 옷을 과하게 물들이지 않는 부드러운 컬러 | 미세한 입자, 낮은 번짐 | `film-fuji160c` |
| 카페·음식 / `signature-cafe-v1` | 따뜻한 목재와 음식, 흰 접시 구분 | 미세 입자, 약한 광원 번짐 | `film-instant690` |
| 풍경 / `signature-landscape-v1` | 녹색·파랑 분리와 밝은 영역 계조 | 매우 약한 질감, 선명도 보존 | `film-elite200` |
| 거리 / `signature-street-v1` | 깊은 그림자와 절제된 채도 | 중간 입자, 번짐 절제 | `film-superia400` |
| 야간 / `signature-night-v1` | 광원 색과 암부 색이 구별되는 컬러 | 암부 입자, 국소 광원 번짐 | `film-ultra100` |
| 흑백 / `signature-mono-v1` | 피부·하늘·그림자의 계조 유지 | 거친 무채색 입자 | `film-neopan1600` |

색 데이터 열은 후보의 출발점이지 해당 필름의 물리적 특성을 측정했다는 주장이나 최종 색감 보증이 아니다. 색감이 역할에 맞지 않으면 후보를 제외한다. 신규 외부 LUT 다운로드는 이번 작업에 포함하지 않는다. 현재 데이터와 자체 조정 곡선을 사용하고 출처와 파생 여부를 기록한다. 제공 LUT 2종은 그대로 유지하되 새 컬렉션의 기반으로 자동 전용하지 않는다.

최종 룩은 **색 LUT + 새 질감의 권장 기본값**이다. 기존 필름 데이터를 그대로 재사용했다면 새 LUT라고 표현하지 않는다. 새 ID의 색 조정과 질감 정의는 버전을 고정하며, 나중에 바뀌면 새 ID/버전으로 추가한다. 제조사·실물 필름의 정확한 복제라고 광고하지 않는다.

색 조정은 프리셋 내부의 LUT 구성으로 구현하고 사용자의 노출·화이트밸런스·뷰티 값을 몰래 변경하지 않는다. 대표 룩 선택이 촬영 모드·날짜·비율·프레임·원본 보관을 바꾸지 않는다.

## 6. 질감과 빛 처리 계약

### 6.1 필름 입자

- 모델 이름은 내부적으로 `film-v2`로 구분한다. 기존 모델은 변경하지 않는다.
- 조절 값은 강도 0~1, 입자 크기 0~1, 컬러 입자 0~1, 암부 가중치 0~1이다. 유한값과 범위를 검증한다.
- 크기 프리셋은 고운/보통/거친 3가지다. 실제 주파수와 진폭 계수는 구현 계획에서 정의하고 테스트 고정값으로 남긴다.
- 기준은 최종 사진의 세로 길이에 대한 비율이다. 출력 해상도와 DPR이 달라도 동일 크기로 화면에 맞춰 보았을 때 질감의 크기가 유사해야 한다. 100% 픽셀 확대가 모든 해상도에서 같다는 뜻은 아니다.
- 밝기 편향을 최소화한 입자를 사용하고 암부 가중치로 분포를 조절한다. 기존 CCD 컬러 노이즈·압축 효과는 별도이며 새 필름 모델에 자동 합치지 않는다.
- 무채색 입자는 흑백 사진에 색을 만들지 않는다. 동일 원본·설정·시드·해상도에서 반복 렌더는 결정적이어야 한다.
- 기존 패턴 version 1의 PRNG와 salt는 바꾸지 않는다. 새 질감에 필요한 난수는 별도 stream을 사용한다. 고정 패턴과 매 컷 패턴 모두 기존 의미를 보존한다.

### 6.2 광원 번짐

- 새 모델은 밝은 광원 마스크를 이용한 국소 번짐으로 한다. 전체 화면 소프트 효과와 분리하며 강도 0에서 효과가 없어야 한다.
- 광원이 거의 없는 중간 회색 사진을 전반적으로 밝히거나 붉게 만들지 않는다. 밝은 흰 면의 중심을 과도하게 착색하지 않는 것을 검증한다.
- LUT 이후 색을 미처리 원본 블러로 덮어써 색감이 사라지는 경로를 피한다.
- 번짐 반경도 사진 크기 기준으로 정의한다. 고품질 효과에 필요한 추가 패스는 새 모델이 활성일 때만 실행하고 자원을 재사용·해제한다.
- 기존 `bloom`, `halation`, `soft` 파라미터 및 효과는 기존 프리셋에서 계속 동일하게 동작한다. 새 룩의 번짐은 별도 값이며 기존 효과를 기본으로 중첩하지 않는다. 수동으로 추가한 효과는 UI에서 구분한다.

### 6.3 강도·해제 규칙

- 기존 ‘색상만’은 LUT 강도만 조절한다. ‘전체 룩’은 LUT와 대표 룩의 질감 강도를 함께 조절한다. 크기·색·시드·모델 버전은 강도에 곱하지 않는다.
- 새 질감의 강도도 기존 ‘그레인 끄기’를 따른다. 기존 일반 그레인의 동작을 변경하지 않는다.
- ‘원본 · 필름 없음’은 LUT와 그 LUT에 딸린 기본 질감을 해제한다. 사용자가 별도로 선택한 추가 질감·렌즈·날짜는 유지하며 현재 안내와 구분되도록 표시한다.
- Studio ‘효과 해제’는 기존 대상에 새 질감까지 포함한다. 보정·뷰티·날짜·구성은 유지한다.
- Studio ‘변경 취소’는 진입 시 모델·모든 질감 값·프로필·시드·컷별 설정까지 복원한다. 닫기는 기존처럼 현재 선택을 유지한다.

## 7. 화면 흐름

기존 검정·보라색 시스템과 중앙 셔터를 유지한다. 이 단계에서는 Studio 탭 구조를 교체하거나 새 카메라 버튼을 추가하지 않는다.

1. 필터 전체 보기의 새 ‘대표 룩’ 그룹에서 후보를 선택한다. 현재 7종 샘플 선택은 그대로 비교용이며 촬영 설정을 변경하지 않는다.
2. 실제 LUT와 권장 질감으로 썸네일을 그린다. 일반 썸네일과 색감 전용 비교의 차이를 계속 안내한다.
3. Studio 효과 탭에 하나의 ‘필름 질감’ 접힘 영역을 둔다. 요약은 ‘기존 / 고운 입자 / 거친 입자’와 활성 강도를 보여준다.
4. 펼치면 기존 처리 또는 새 필름 처리를 명시적으로 선택하고 입자·번짐을 조절한다. 상세 값은 ‘세부 조정’ 안에 둬 처음부터 슬라이더를 모두 펼치지 않는다.
5. 현재 사진의 ‘질감 전 / 질감 적용’을 같은 고정 시드로 확인하는 정지 미리보기를 제공한다. 두 장은 같은 LUT·수동 보정·비율을 사용하고 새 필름 질감만 다르게 한다. 첫 버전에서는 뷰티·렌즈·날짜·추가 우연성을 양쪽 모두 제외하고 ‘색감·보정에 필름 질감만 비교’라고 표시한다. 완전한 최종 저장 결과나 RAW 비교라고 부르지 않는다. 기존 LUT A/B는 색감 전용으로 남겨 의미를 바꾸지 않는다. 비교는 닫을 때 설정을 변경하지 않는다.
6. 설정 요약·전체 설정 검사에 모델과 현재 유효값을 반영한다. 원본 선택, 비활성 상태, 수동 추가 질감은 구분한다.

기존 ‘은은한 질감’은 기존 프리셋에서 유지한다. 새 모델에서는 그 역할을 새 강도 설정이 담당하므로 동시에 두 번 약화하지 않는다. UI에서 새 모델 적용 중에는 그 이유를 보여준다. 네컷·하프 첫 컷 이후 효과 잠금은 새 조절·레시피 적용·설정 이동에서도 그대로 적용한다.

## 8. 데이터·렌더 경계

- `CameraSettings`에 선택형 필름 처리 설정을 추가한다. 저장 시 모델 버전, 선택한 프로필 ID/버전, **해결된 질감 수치**를 함께 보관한다. 카탈로그 기본값을 나중에 다시 조회해서 과거 값을 바꾸지 않는다.
- 해당 필드가 없는 기존 데이터는 기존 모델을 사용한다. 기존 사진과 레시피에 필드를 일괄 삽입하지 않는다. 알 수 없는 버전이나 손상된 값은 안내하고 적용을 차단하며 조용히 다른 모델로 바꾸지 않는다.
- 현재 질감 설정도 기존 설정처럼 로컬에 기억한다. 재시작·복귀 시 검증한 동일 값으로 복원하며 카메라 track을 재시작하지 않는다. 새 프로필 ID가 있는데 필요한 처리 스냅샷이 빠진 기록은 손상된 새 데이터로 구분한다. 이를 정상적인 과거 데이터와 혼동해 기본값으로 재현상하지 않는다.
- 새 프로필을 선택하고 아직 수동 조정하지 않은 경우만 그 프로필 기본값을 사용한다. 수동 조정 시 해결된 값으로 전환한다. 기존 필터 선택 시 새 프로필 기본 질감은 제거하고 사용자가 명시적으로 켠 추가 질감만 유지한다.
- `CapturedFrame`, 컷별 `frameSettings`, `CaptureRecord`에 선택 당시 값이 들어가야 한다. 합성에서는 사진 영역에만 질감을 적용하고 흰 종이·프레임·문구·날짜에는 적용하지 않는다.
- 원본 재현상은 새로 선택한 전체 룩과 보관된 컷별 패턴을 사용한다. 첫 컷 이후 잠금, 과거 기록 보존, 새 결과 별도 저장은 기존 계약을 따른다.
- 레시피 validation과 Studio snapshot에 선택형 설정을 연결한다. 내보내기·전체 촬영 구성 저장은 2단계 범위다.
- GPU 모델 선택과 파라미터 전달은 한 resolver로 통합한다. App에서 실시간·저장·재현상별로 다른 계산식을 복제하지 않는다.

예정 책임 경계:

| 파일/모듈 | 책임 |
| --- | --- |
| 새 `src/engine/filmQuality.ts` | 설정 검증·기본값·모델/프로필 해결·강도 의미 |
| 새 `src/engine/signatureFilms.ts` + `src/engine/lut.ts` | 새 후보의 색감/질감 정의와 기존 카탈로그 연결 |
| `src/engine/types.ts`, `look.ts`, `pipeline.ts`, `shaders.ts` | 선택형 새 경로, 기존 분기 보존, 자원 수명 |
| `src/capture/types.ts`, `recipes.ts`, `reprocess.ts`, `src/App.tsx` | 현재·컷별 설정 전달, 스냅샷·잠금·취소·저장 |
| 새 `src/components/FilmQualityControls.tsx` + `CreativeSettings.tsx` | 접힘 영역, 명시적 선택, 유효 상태 |
| `thumbs.ts`, `StudioFramePreview.tsx`, 설정 요약·검사 컴포넌트 | 실제 룩 미리보기, 모델 포함 캐시 키, 읽기 전용 상태 |
| 새 전체 룩 정지 비교 모듈/컴포넌트 | 동일 원본·시드의 비교, 취소·자원 해제; 색감 A/B와 분리 |

이는 책임 설계이며 구현 순서/세부 함수/테스트 코드의 실행 계획은 아니다. 첫 단계에서 임의로 App 전체 리팩터링이나 새로운 저장소를 도입하지 않는다.

## 9. 실패·성능·접근성

- LUT/모델 로드 실패는 실패 상태를 보여주고 해당 룩 적용을 막는다. 원본을 성공한 필터 결과처럼 표시하지 않는다.
- 정지 미리보기는 긴 변 최대 1024로 제한한다. 공유 렌더러 작업은 순차 처리하고 변경·닫기 때 이전 요청을 무효화한다. 신규 서버 업로드는 없다.
- 원본 없는 저장 사진에는 재현상 비교를 제공하지 않는다. 외부 입력이 이미 보정됐을 가능성과 RAW가 아니라는 설명을 유지한다.
- 새 광원 패스가 준비되지 않으면 새 모델 저장 성공을 표시하지 않는다. 사용자는 명시적으로 기존 모델을 선택할 수 있다.
- 모델 off 상태에서 추가 GPU 패스가 발생하지 않아야 한다. 새 질감용 버퍼는 캡처 크기 변경·종료·context loss에서 해제/재생성한다.
- 작은 화면에서도 하단 해제·취소·닫기를 사용할 수 있게 한다. 포커스 트랩·Escape·트리거로 포커스 복귀·키보드 조작·선택 상태 라벨을 제공한다.

## 10. 검증과 출하 조건

### 자동 테스트

- 설정 부재→기존 모델, 버전/범위 오류→명시적 실패, 새 레시피 저장·복원.
- 기존 룩을 고정 시드와 실제 입력 fixture로 실행해 변경 전후 픽셀 일치 확인. JPEG 파일 해시만으로 GPU 결과 일치 판정을 대체하지 않는다.
- 새 질감 off·강도 0의 픽셀 일치, 무채색 입자 RGB 동등성, 결정적 반복 렌더, grain mute, 새 모델 선택/해제 경계.
- 같은 사진을 512/1024/2048로 렌더한 뒤 같은 표시 크기로 맞춰 입자 공간 주파수와 번짐 범위를 비교한다. 허용 오차와 기준 이미지는 구현 계획에서 고정한다.
- 중간 회색·밝은 점·큰 흰 면 fixture로 무광원 변화, 번짐 국소성, 하이라이트 착색을 확인한다.
- 필터 선택이 노출·날짜·뷰티·비율·촬영 모드를 바꾸지 않는지, 취소가 모델·시드·컷별 상태를 복원하는지 검증.
- 실시간 프레임/동일 원본 저장/재현상에서 해결된 설정 일치. 합성 종이·문구에는 질감이 적용되지 않음.
- 썸네일 캐시의 모델·값·프로필 버전 분리, 빠른 전환·닫기·로드 실패 처리.
- 기존 최근 촬영·레시피·Studio 취소·다중노출·네컷 잠금·모든 비율·전면 복귀 테스트 유지.
- 새 회귀 테스트의 RED→GREEN, typecheck, build, 관련 테스트와 전체 suite를 출하 전 확인한다.

### 사진·기기 확인

- 기존 AI 샘플 7종은 비교 데모다. 이를 실제 카메라·피부 품질 증거로 표현하지 않는다.
- 사용/보관 권한이 있는 실제 사진으로 인물·음식·풍경·거리·야간·실내를 검증한다. 다양한 피부색·역광·흰 물체·어두운 영역을 포함한다. 권한 확인된 실제 입력이 없으면 후보를 ‘미검증’으로 기록하고 품질 완료 판정을 보류한다.
- 후보별 기존 결과/새 결과/질감 off를 같은 원본으로 기록한다. 차이가 미미하거나 색·계조를 망가뜨리는 후보는 제외한다.
- 320×568, 390×844, 844×390, 1280×800을 한 번에 확인하고 결함을 묶어 수정한 뒤 한 번 재확인한다.
- 실제 iPhone 15 Pro Max Safari/PWA의 촬영·앱 복귀·네컷·발열·큰 사진 저장은 별도 확인한다. Chromium 합성 카메라 테스트를 실기기 증거로 표현하지 않는다.
- 기존 임시 HTTPS preview를 확인 용도로 재사용한다. 새 장기 서버/터널을 계속 추가하지 않는다. push·Vercel 정식 배포는 별도 요청에 따른다.
