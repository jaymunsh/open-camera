# Open Camera — 재사용 가능한 빈티지 우연성

작성일: 2026-10-05 (Asia/Seoul)
상태: 2026-10-05 사용자 문서 승인. 구현 계획 검토 및 실행 방식 선택 대기. 제품 코드 구현 전.

## 목적과 확정 범위

비슷한 필터 이름을 늘리는 대신, 사진마다 달라지는 아날로그 질감을 추가한다. 사용자는 효과 설정을 재사용하고, 마음에 든 패턴을 고정할 수도 있어야 한다. 기존 필터·촬영·원본 보관 기능은 유지한다.

사용자는 영상 기능을 제외하고 다음 네 기능의 추진 방향을 승인했다. 서로 독립적인 시스템이므로 이번 문서는 첫 번째 기능만 설계한다.

1. 빈티지 우연성: 추가 질감 조절, 매 컷 새 패턴, 패턴 고정, 레시피 재사용, 원본에서 다른 현상.
2. 입체 GIF: 좌·중앙·우 촬영 가이드, 왕복 재생과 속도 조절, GIF 저장. 별도 설계 및 인코딩·정렬 검증 필요.
3. 장노출 합성: 잔상/빛 궤적, 촬영 시간, 진행 미리보기와 취소. 실제 센서 셔터 제어가 아닌 프레임 합성. 별도 설계 필요.
4. 필름 시트: 촬영모드가 아니라 여러 사진을 선택하는 편집 기능. 가져오기, 순서, 칸 수, 여백, 번호, 제목과 단일 이미지 저장. 강제 롤 채우기·현상 대기는 제외. 별도 설계 필요.

후속 기능의 개별 설계·구현·검증은 이 문서로 승인된 것으로 간주하지 않는다. 카메라 복귀 문제, 비율 정렬, 기존 스튜디오 기능 개선과 운영 배포는 이번 변경 범위가 아니다.

## 현재 코드에서 확인한 조건

- `src/App.tsx`: `fxSeedRef`는 필터 ID 변경 때만 재생성된다. 일반 촬영은 `applied.fx`를 사용한다. 네 컷은 첫 장의 설정과 FX를 고정한다.
- `src/engine/shaders.ts`: 빛샘과 먼지는 seed에 의존한다. 입자와 색 노이즈는 시간과 grain texture에도 의존한다.
- `src/engine/pipeline.ts`: `makeGrainTile()`은 `Math.random()`으로 렌더러별 입자 타일을 만든다. seed만 저장해서는 새로고침 뒤 입자 패턴을 재현할 수 없다.
- `src/capture/recipes.ts`: 버전 1 레시피, 최대 20개, `oc-recipes` 로컬 저장. 설정을 검증하지만 현재 seed는 레시피 대상이 아니다.
- `src/capture/types.ts`: 결과물은 `settings`, 합성 사진은 `frameSettings`도 저장한다. 실제 프레임 FX는 메모리에만 있다.
- `src/capture/reprocess.ts`: 현재 재현상은 모든 원본에 같은 FX를 적용한다. 프레임별 패턴을 복원하려면 확장이 필요하다.
- `src/capture/store.ts`: 최근 결과 10개/Blob 합계 50 MiB. 이번 기능으로 한도를 늘리거나 기존 데이터베이스를 초기화하지 않는다.
- 이전 스튜디오·날짜·빈티지 프리셋 작업이 미커밋 상태다. 이를 보존하며 별개의 완료 작업으로 취급한다.

## 접근 방식

권장 방식은 **선택적 설정 + 공통 패턴 해석기**다. 기본 설정과 패턴을 입력으로 받아 파생 보정값과 FX를 계산하고, 촬영·편집·재현상에서 함께 사용한다. 기존 프리셋 데이터는 수정하지 않는다.

대안으로 기존 프리셋 자체를 무작위화하면 기본 결과 보존을 위반한다. 촬영 모드마다 별도로 구현하면 미리보기·저장·재현상 규칙이 달라지므로 채택하지 않는다.

새 선택을 끈 경우 공통 해석기는 기존 입력을 그대로 반환하고, 추가 GPU 처리나 새로운 입자 타일을 만들지 않는다.

## 사용자 동작

### 위치와 추가 질감

스튜디오 → 효과에 `빈티지 우연성` 섹션을 추가한다. 새 필터나 촬영모드를 만들지 않는다.

- 방식: `꺼짐 / 매 컷 새롭게 / 패턴 고정`. 초기값은 꺼짐.
- 네 조절값: `추가 입자 / 추가 빛샘 / 추가 먼지 / 색 편차`, 각각 0–100%.
- 처음 켤 때 제안값: 입자 20%, 빛샘 15%, 먼지 10%, 색 편차 15%. 이후 껐다 켜도 사용자의 값을 유지한다.
- 0%는 해당 **추가 효과**를 끈다. 선택한 필터에 원래 있는 효과까지 지운다는 뜻은 아니다. 이를 화면에 명시한다.
- `다른 패턴`: 현재 패턴을 바꾸되 필터·조절값·날짜·렌즈·비율은 유지한다.
- `이 패턴 고정`: 지금 보이는 seed를 유지하며 패턴 고정으로 전환한다.
- `레시피 저장`: 기존 레시피 창을 사용하고 새 저장소를 만들지 않는다.

기존 강도/은은한 질감 옵션은 프리셋 효과에 계속 적용한다. 새 추가 효과는 그 이후 별도 강도로 적용한다. 따라서 필터 강도 0%여도 명시적으로 켠 추가 효과가 남을 수 있다. 기존 `입자 끄기`가 켜져 있으면 프리셋·추가 입자를 넣지 않는다. 수동 보정의 입자값은 기존 규칙을 유지하며, 다른 추가 효과는 끄지 않는다.

### 미리보기와 촬영

`매 컷 새롭게`는 다음 촬영에 사용할 seed를 미리 생성한다. 슬라이더 변경·단순 재렌더링·설정 창 열기·카메라 복귀로 새 seed를 만들지 않는다. 촬영 시 현재 seed를 고정하고, 프레임 생성 성공 뒤 다음 seed를 준비한다. 실패하면 같은 seed로 재시도한다.

`패턴 고정`은 앱 새로고침·필터 변경·전후면 전환에도 seed를 유지한다. 패턴은 사진의 정규화된 좌표를 기준으로 하므로 다른 비율/해상도에서 완전히 같은 픽셀 이미지를 보장하지는 않는다.

촬영과 이미지 편집 미리보기에는 고정된 패턴 시간/타일을 사용한다. 신규 모드에서 패턴이 매 프레임 반짝이거나 저장 직전 다시 무작위화되지 않아야 한다. 기존 JPEG 열화 효과의 미리보기 근사와 저장 후 압축 차이는 그대로 존재한다.

일반·즉석사진·하프프레임·네 컷·다중노출을 지원한다. 패턴 고정에서는 각 컷에 같은 seed를, 매 컷 새롭게에서는 컷마다 다른 seed를 기록한다. 네 컷의 첫 장 설정 잠금은 유지하되 새 방식의 seed만 컷마다 바뀐다. 한 장 재촬영 시 다른 컷의 패턴과 사진은 유지한다.

## 설정·촬영 데이터

### 재사용 가능한 설정

`CameraSettings`에 선택적 `variation`을 추가한다.

내용은 알고리즘 버전 1, 방식(off/new/fixed), 네 개의 0–1 강도, 고정 seed다. seed는 유한한 0 이상 1 미만 값이며 새로운 seed 생성 시 직전 값과 같지 않아야 한다. 값 누락은 기존 버전 1 레시피와 촬영 데이터를 위해 꺼짐으로 해석한다.

강도·방식·고정 seed를 버전이 있는 전용 로컬 설정 키 `oc-film-variation`에 저장한다. 새 방식의 다음 컷 seed는 세션 상태이며, 사용자가 고정하지 않은 임시 seed는 레시피의 고정 패턴으로 저장하지 않는다.

레시피 외형 버전 1은 유지하고 추가 설정 자체에 알고리즘 버전을 둔다. 기존 레시피를 적용하면 새 옵션은 꺼짐으로 돌아간다. 새 레시피가 매 컷 새롭게라면 같은 강도만 복원하고 새로운 seed를 준비한다. 패턴 고정이면 seed도 복원한다. 잘못된 값/미지원 알고리즘 버전은 안내하며 레시피 전체를 부분 적용하지 않는다.

### 실제 촬영 패턴

재사용할 설정과 실제 촬영 seed는 구분한다. `CapturedFrame`에 선택적 패턴 스냅샷을 추가하고, `CaptureRecord`에 프레임 순서와 일치하는 선택적 패턴 배열을 저장한다. 각 스냅샷은 버전과 실제 seed를 가진다. 새 기능을 쓰지 않은 프레임은 배열의 해당 위치를 null로 둔다. 일반 사진도 한 원소 배열로 같은 규칙을 쓴다. 모드별 프레임 수와 배열 길이/요소 값을 검증하며, 잘못된 메타데이터로 원본을 재현상하지 않는다.

일반/합성 촬영은 입력·설정·seed를 첫 비동기 처리 전에 고정한다. 저장 재시도는 새 패턴을 생성하지 않는다. 패턴 메타데이터는 원본 보관을 끈 경우에도 기록할 수 있지만, 원본 없는 사진에 재현상이 가능하다고 표시하지 않는다.

기존 레코드는 패턴 필드가 없어도 읽을 수 있다. IndexedDB 스키마를 재생성하거나 데이터 삭제·자동 레시피 마이그레이션을 하지 않는다.

## 렌더 구조와 책임

- 새 `src/engine/variation.ts`: 검증/기본값, seed에 따른 결정적 수치 생성, 기본 보정값과 FX에서 추가 효과 계산. React·저장소·GPU를 알지 않는 순수 모듈.
- 새 `src/capture/variation.ts`: 로컬 설정 직렬화/검증과 다음 컷 패턴 관리 보조. 레시피·촬영 스냅샷은 기존 모듈과 명시적으로 연결한다.
- `src/engine/pipeline.ts` 및 필요한 셰이더: 신규 모드에서만 결정적 입자 타일과 고정 noise 시간/좌표 사용. 기존 무작위 타일은 기존 경로용으로 유지한다. 타일은 렌더러당 현재 패턴 하나만 캐시하며 교체/컨텍스트 복원 시 GPU 자원을 정리한다.
- `src/App.tsx`: 파생 룩을 촬영/편집에 연결한다. seed 규칙과 파생 수식을 여러 이벤트 핸들러에 복사하지 않는다.
- `src/capture/useCreativeCapture.ts`: 실제 패턴 스냅샷을 저장하고 프레임 교체 시 대응 메타데이터도 교체한다.
- `src/capture/reprocess.ts`: 프레임별 패턴으로 원본을 다시 처리한다. 합성 레이아웃·문구·날짜는 기존 합성 경로에서 처리한다.
- 스튜디오의 전용 하위 컴포넌트: 방식/강도/패턴 변경과 레시피 진입. 기존 스튜디오 탭과 촬영 잠금을 재사용한다.

추가 입자·빛샘·먼지는 기존 효과를 재사용한다. 추가량 상한은 각각 grain 0.35, leak 0.30, dust 0.12로 시작하고 최종 효과는 0–1로 제한한다. `원본` 필터도 새 옵션을 명시적으로 켜면 추가 질감을 적용할 수 있다.

색 편차는 seed로 노출 ±0.08 EV, 색온도 ±0.04, 틴트 ±0.02 범위 안의 파생 offset을 만든다. 각 상한에 색 편차 강도를 곱하며 최종 보정값은 `PARAM_DEFS` 범위를 지킨다. 기본 수동 보정값이나 LUT 자체는 수정하지 않는다. 같은 seed로 강도를 조절하면 편차 방향은 유지되고 크기만 달라진다.

이 수치는 새 기능만의 초기 계수다. 사용자 승인 기능을 벗어나지 않는 시각 조정은 실제 비교 이미지로 검증하고 변경 계수를 기록한다. 이번 단계는 하이라이트 번짐 알고리즘이나 종이 질감을 새로 만들지 않는다.

## 다른 현상과 결과 보존

원본이 있는 사진의 기존 `다시 현상` 화면에 `다른 패턴`과 `패턴 고정`을 제공한다. 진입만으로 자동 재추첨하지 않는다. 새 기능으로 찍은 사진은 저장된 강도와 실제 프레임 seed를 복원한다.

합성 사진에서 같은 패턴 유지 재현상은 원래 프레임별 seed를 유지한다. `다른 패턴`은 각 프레임에 새 seed를 만든다. `패턴 고정`을 선택하면 현재 기준 패턴(마지막 프레임 seed)을 전체 프레임에 적용하고 안내한다. 기존의 전체 프레임 공통 필터 편집 방식은 유지한다.

별도 결과 저장은 새로운 ID를 쓰고 패턴 메타데이터를 포함한다. 원래 결과를 덮어쓰지 않는다. 최근 10개/50 MiB의 기존 정리 정책으로 오래된 결과가 밀릴 수 있다는 보관 조건은 유지한다. 사용자가 직접 저장한 사진 파일을 삭제하지 않는다.

원본이 없는 사진은 재현상 진입을 비활성화하고 원본 보관이 필요하다고 안내한다. 원본 JPEG/미용 보정/브라우저 색 처리 차이 때문에 재현상 결과가 최초 촬영본과 픽셀 단위로 같다고 약속하지 않는다. 동일 입력·설정·패턴에서 추가 효과가 재현되는 것이 검증 대상이다.

## 실패와 성능 조건

- 새 옵션을 끈 경우 기존 촬영 출력·프리셋 정의·렌즈·날짜·비율·원본 보관 동작을 유지한다.
- 메타데이터 검증 실패 시 손상 데이터를 덮어쓰지 않고 안내한다. 앱 시작 시 새 옵션만 꺼짐으로 안전하게 진행한다.
- 설정 저장 실패 시 현재 세션에서 사용 가능하되 다음 실행에 유지되지 않을 수 있음을 표시한다.
- 미리보기 및 재현상 비동기 작업은 세대/취소 규칙을 사용해 늦게 끝난 작업이 최신 패턴을 덮어쓰지 못하게 한다.
- 네 컷 진행 중과 사진 인코딩 중 옵션 변경/레시피 적용을 기존 잠금 규칙에 맞춰 막는다.
- 입자 타일을 매 프레임 업로드하거나 전체 사진 버퍼를 패턴 수만큼 누적하지 않는다. 새 의존성·외부 폰트·이미지 에셋은 필요하지 않다.
- GPU 생성/컨텍스트 복원 실패 시 조용히 다른 패턴으로 저장하지 않고 추가 옵션을 끄도록 안내한다. 기존 촬영을 사용할 수 있게 유지한다.

## 검증과 완료 기준

1. 꺼짐/설정 없음에서 기존 파생 보정값·FX가 변경되지 않음. 기존 레시피/사진을 삭제 없이 읽고 적용 가능.
2. 같은 입력·seed·강도·알고리즘 버전에서 결정적 파생값과 추가 질감 재현. 패턴 변경 시 빛샘/먼지 배치와 색 편차가 실제로 달라짐.
3. 렌더러 재생성·컨텍스트 복원·새로고침 뒤 패턴 고정 유지. 해상도 차이에 대한 픽셀 동일성은 요구하지 않음.
4. 매 컷 방식은 성공한 촬영만 다음 seed로 진행. 실패/저장 재시도/단순 상태 변경이 현재 패턴을 바꾸지 않음.
5. 일반·즉석사진·하프·네 컷 자동/수동·다중노출의 패턴 스냅샷과 결과가 대응. 한 컷 재촬영이 다른 컷을 변경하지 않음.
6. 레시피 저장/재적용에서 강도와 방식 복원. 고정 패턴은 복원하고 매 컷 방식은 새 패턴으로 시작. 잘못된 데이터는 부분 적용/삭제하지 않음.
7. 원본 재현상에서 패턴 유지/변경이 동작하고 별도 결과 저장. 원본 없는 사진·손상된 메타데이터·저장 실패 처리 확인.
8. 조절값 0%, 최대값, 기존 입자 끄기/전체 룩/은은한 질감/날짜/사용자 LUT의 조합과 출력 경계 확인.
9. 430×932, 가로 화면, 데스크톱에서 조절·키보드·스크린리더 이름·잠금·오류 안내 확인. 동일 샘플로 꺼짐/고정/서로 다른 패턴 비교 이미지 기록.
10. `npm run typecheck`, 전체 Playwright 테스트, `npm run build`, `git diff --check` 통과. 카메라·저장·복귀의 물리적 iPhone 검증은 실제 수행 여부를 구분해 보고.

완료 후 기존 임시 HTTPS 미리보기 또는 새 미리보기로 확인할 수 있게 한다. 이번 설계 승인에 운영 push·Vercel 배포 권한을 포함하지 않는다.

## 자체 검토와 다음 단계

- 이번 문서는 첫 기능만 다루며 GIF/장노출/필름 시트 구현을 끼워 넣지 않는다.
- 기본 꺼짐, 기존 데이터 호환, 사용자 설정과 촬영 seed 분리, 네 컷 설정 잠금과 seed 변화의 관계를 명시했다.
- 다른 현상은 원본에서만 실행하며 저장 결과 보존과 기존 보관 한도를 구분했다.
- 고정 패턴과 픽셀 동일한 원본 복원의 차이, 기존 프리셋 강도와 추가 강도의 차이를 명시했다.
- 사용자 문서 검토 후 구현 계획을 작성하고 실행 방식을 선택한다. 현재는 구현/설치/운영 배포를 시작하지 않는다.
