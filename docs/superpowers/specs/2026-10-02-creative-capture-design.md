# Open Camera — 기존 촬영을 유지하는 새 촬영 기능

작성일: 2026-10-02 (Asia/Seoul)
상태: 기능 범위 승인 완료, 이 문서의 세부 설계는 사용자 검토 대기. 아직 구현하지 않음.

## 목적과 보존 조건

사용자는 UI 전반의 재설계보다 사진을 만드는 기능을 원한다. 최근 촬영 확인, 하프프레임, 다중노출, 선택 가능한 빈티지 개선을 추가하고 날짜에 작은 빨간 아날로그 글씨 스타일을 제공한다.

“기존꺼는 건드리지말구”를 다음처럼 해석한다.

- 기본 모드는 계속 일반 촬영이다. 일반 촬영의 기존 공유/다운로드 흐름을 유지한다.
- 기존 프리셋/LUT 파일, 프리셋 효과 값, 기본 강도 동작을 바꾸지 않는다.
- 기존 주황색 날짜 스타일, 날짜 켜기/자동/끄기, 형식/크기/방향 설정을 유지한다.
- 모든 촬영 비율의 중앙 정렬, iOS 상단 불투명 영역, 카메라 전환, 타이머, 미용 보정, 이미지 편집, 사용자 LUT 저장을 보존한다.
- 새 기능은 사용자가 명시적으로 선택했을 때만 기존 출력에 영향을 준다. 최근 촬영 보관은 촬영 결과의 별도 로컬 사본이며 출력 자체를 변경하지 않는다.

아래의 합성 비율, 보관 한도, 새 옵션의 초기값은 구현을 위해 제안하는 세부 사항이다. 기존 대화에서 각각을 따로 승인받은 것으로 간주하지 않는다.

## 접근 방식

1. **추가 모드/옵션 방식 — 권장:** 기존 경로를 기본값으로 유지하고 새 촬영 상태와 합성·보관 모듈을 분리한다. 기존 결과를 보존할 수 있으나 선택 옵션이 늘어난다.
2. **기존 동작 교체:** 강도를 전체 효과에 적용하고 모든 빈티지 프리셋을 재조정한다. 설정은 단순하지만 같은 필터를 다시 찍었을 때 결과가 달라져 보존 요청에 맞지 않는다.
3. **별도 실험 앱:** 기존 앱과 완전히 분리한다. 결과 비교는 쉽지만 배포·설정·사진 관리가 이중화된다.

1번을 사용한다. 한 가지 촬영 결과 생성 흐름에 연결되는 기능 묶음으로 진행하되, 보관 → 합성 모드 → 날짜/질감 옵션 순서로 검증 가능한 단위를 나눈다. 필터 목록이나 앱 전체 디자인은 재구성하지 않는다.

## 1. 최근 촬영 확인

- 이 앱의 카메라로 생성한 완성 사진만 보관한다. 일반 촬영, 하프프레임 완성본, 다중노출 완성본을 포함한다. 편집 모드의 외부 사진 저장과 미완성 첫 장은 포함하지 않는다.
- 최근 사진 진입점은 기존 메뉴에 추가한다. 목록과 크게 보기, 다시 공유/다운로드, 개별 삭제를 제공한다. 초기 버전에서는 기존 촬영 화면에 상시 썸네일을 추가하지 않는다.
- 일반 촬영은 지금처럼 바로 공유/다운로드를 시도한다. 공유를 취소해도 성공적으로 생성한 사진은 최근 촬영에 남는다. 목록에서는 이를 사진 앱에 저장됐다고 표시하지 않는다.
- 별도의 IndexedDB 데이터베이스 `oc-captures` v1에 최종 JPEG Blob, 촬영 시각, 출력 크기, 촬영 모드, 파일명을 저장한다. 기존 `oc-store`/`lut-files`는 업그레이드하거나 삭제하지 않는다.
- 보관 한도는 최근 **10장 및 JPEG 합계 50 MiB 이하**다. 새 사진 추가와 가장 오래된 사진의 정리는 같은 트랜잭션으로 처리한다. 추가 실패 시 이전 사진을 먼저 잃지 않는다.
- 단일 사진이 50 MiB를 초과하거나 저장소가 거부/실패하면 공유는 계속 가능하게 하고, 현재 세션에서는 최근 사진을 확인할 수 있게 한다. “기기에 보관하지 못함”을 알리며 영구 저장 성공으로 표시하지 않는다.
- 보관 작업 때문에 공유 API 호출을 더 늦추지 않는다. 비동기 보관과 기존 공유 흐름은 별도로 처리하고 실패도 구분한다.
- 사진은 서버에 업로드하지 않는다. iOS 전체 사진첩을 읽지 않는다. 브라우저 데이터 삭제나 저장소 정리로 사라질 수 있는 임시 보관임을 안내한다.

## 2. 하프프레임

- 촬영 메뉴에 `일반 / 하프프레임 / 다중노출`을 추가한다. 새로 시작할 때 기본은 일반이며, 선택 모드는 재실행 후 유지하지 않는다.
- 하프프레임은 세로 **3:4 사진 두 장**을 왼쪽/오른쪽 순서로 붙여 최종 **3:2 사진**을 만든다. 검은 테두리, 필름 구멍, 장식 문구는 넣지 않는다.
- 첫 셔터는 첫 사진을 메모리에 고정하고 `1/2 → 2/2`로 진행한다. 아직 공유·최근 촬영 보관을 하지 않는다. 첫 장을 확인하고 취소/다시 찍을 수 있다.
- 두 번째 셔터 뒤 완성 미리보기를 보여준다. 여기서 저장/공유 또는 두 번째 장 다시 찍기를 선택한다. 재촬영은 첫 장을 유지한다.
- 두 장 사이에 필터/보정이나 전후면 카메라를 바꿀 수 있다. 각 사진에는 해당 셔터 시점의 설정을 독립적으로 적용한다. 첫 장을 나중 설정으로 재처리하지 않는다.
- 이 모드에서는 사진 비율을 3:4로 고정하고 기존 일반 촬영 비율 선택을 일시 비활성화한다. 모드를 나가면 이전 일반 촬영 비율을 복원한다.
- 날짜는 각 장이 아닌 최종 합성본에 한 번만 표시한다. 날짜 설정과 날짜 시각은 두 번째 촬영 시점에 고정한다.

## 3. 다중노출

- 초기 버전은 **두 장 합성**이다. 첫 촬영 시 현재 비율을 고정하고 첫 장을 메모리에 보관한다.
- 두 번째 촬영 단계에서 첫 장을 35% 불투명도로 촬영 영역에 겹쳐 구도를 맞춘다. 검은 여백/컨트롤에는 겹치지 않는다. 안내 오버레이는 최종 사진에 별도로 추가하지 않는다.
- 두 번째 장은 첫 장과 같은 출력 크기/크롭으로 만든다. 모드가 끝날 때까지 비율을 잠근다. 전후면 전환과 필터 변경은 허용하되 각 장의 설정은 독립적으로 고정한다.
- 촬영 후 미리보기에서 `겹침 비율`을 조절한다. 기본은 50%이며 범위는 0–100%다. RGB 결과는 `(1 - 비율) × 첫 장 + 비율 × 두 번째 장`의 sRGB 가중 혼합이다. 실제 필름의 물리적 노출 재현이라고 설명하지 않는다.
- 혼합 비율 조절은 원본 두 장에서 다시 계산하므로 재조절에 따른 열화가 없다. 날짜는 합성 뒤 한 번만 그린다.
- 저장/공유 시 최종본을 최근 촬영에 추가한다. 다시 찍기는 두 번째 장만 버리고 첫 장을 유지한다. 전체 취소는 둘 다 해제한다.

## 4. 강도와 빈티지 질감 — 기존 기본값은 유지

- 기존 강도 슬라이더에 `색상만 / 전체 룩` 선택을 추가한다. 기본 `색상만`은 현재처럼 LUT만 약하게 만들고 프리셋 효과는 유지한다.
- 선택한 `전체 룩`에서는 같은 강도로 LUT와 프리셋의 수치형 효과를 함께 줄인다. 0%는 프리셋 색상/질감 효과가 꺼진다. 별도로 조절한 노출·미용 보정과 날짜는 유지한다. `seed`는 강도와 함께 줄이지 않는다.
- 추가 선택 `질감: 기존 / 은은하게`의 기본은 `기존`이다. 기존 프리셋 정의나 렌더링 기본값은 변경하지 않는다.
- `은은하게`는 `디지캠` 그룹 이외의 프리셋 중 grain/leak/halation/soft 효과가 있는 경우에만 제공한다. 입자 크기와 grain 강도는 기존의 50%, leak 강도는 25%, halation/soft 강도는 50%로 시작한다. 없는 효과는 새로 켜지 않고 나머지 효과 값은 유지한다. CCD 픽셀·밴딩·플래시 효과를 필름처럼 바꾸지 않는다.
- 은은한 빛샘은 가장자리에서 기존 마스크를 유지하고 사진의 바깥쪽 20% 구간에서 안쪽으로 부드럽게 감쇠시켜 중앙에서는 0이 되도록 한다. 합성 전 각 사진의 크롭 영역을 기준으로 한다.
- 새 질감은 명시적인 렌더 옵션으로 분리한다. 옵션이 없으면 현재 셰이더 경로와 같은 출력을 사용한다. 위 초기 계수를 같은 입력/고정 seed 비교 이미지로 확인하고, 결과가 기대와 다르면 새 옵션의 계수만 조정하여 변경값을 기록한다.
- `전체 룩`과 `은은하게`는 서로 다른 옵션이다. 전자는 효과의 양, 후자는 질감의 형태를 조절한다. 새 옵션은 기본으로 저장하지 않고 세션에서 선택한다.

## 5. 작은 빨간 아날로그 날짜

- 기존 날짜 설정에 `주황 디지캠 / 빨간 아날로그`를 추가한다. 기존 사용자와 새 사용자의 기본은 주황 디지캠이다. 새 스타일 선택만 별도 설정 키에 저장한다.
- 빨간 스타일은 작은 모노스페이스 숫자, 단일 색 `#C94F43`, 굵은 검은 외곽선/발광 효과 없이 표현한다. 새 외부 폰트 다운로드는 추가하지 않는다.
- 날짜 형식은 현재의 다섯 가지를 그대로 사용한다. `'26 10 02`처럼 단순한 표시가 가능하다. 빨간 스타일은 기존 크기 단계 대비 약 60% 높이로 시작하고 실제 사진에서 시각 확인한다.
- 미리보기와 내보내기는 같은 빨간 글자 렌더러와 배치 계산을 사용한다. 작은 출력에서 읽기 위한 미리보기 전용 과도한 확대는 하지 않는다.
- 빨간 스타일은 전체 글자 폭/높이가 사진 내부 여백에 들어오도록 축소한다. 세로 방향과 좁고 긴 사진도 경계 밖으로 잘리지 않는다.
- 주황 스타일은 기존 표현/배치를 그대로 둔다. 스타일을 바꾸면 날짜를 끄거나 형식/크기를 초기화하지 않는다.
- 일반 촬영/편집은 기존 날짜 시각 동작을 유지한다. 새 합성 모드에서는 완성 날짜 시각을 고정해 혼합 슬라이더를 조절해도 날짜가 바뀌지 않는다. EXIF 날짜 추출/임의 날짜 입력은 이번 범위에 넣지 않는다.

## 모듈과 데이터 흐름

현재 `App.tsx`는 일반 촬영에서 `exportFiltered(video, ...) → saveImage(blob, name)`를 호출한다. `pipeline.ts`가 필터와 날짜를 렌더링하고 JPEG를 생성한다. 이 경로를 기본으로 유지한다.

- `capture` 모듈: 새 모드의 상태 및 셔터 시점 스냅샷을 관리한다. `대기 → 첫 장 촬영 중 → 두 번째 장 대기 → 두 번째 장 촬영 중 → 완성 확인 → 출력 중` 상태를 명시적으로 구분한다.
- `composite` 모듈: 고정된 두 이미지의 크롭/하프프레임/혼합과 날짜 없는 최종 캔버스를 만든다. 카메라나 저장소에 의존하지 않는다.
- `captureStore` 모듈: JPEG 보관/조회/삭제/한도만 담당한다. 사용자 LUT 저장소와 공유 UI에 의존하지 않는다.
- 최근 사진/완성 확인 컴포넌트: 상태에 맞는 확인·재촬영·공유만 제공한다. 기존 편집 모드와 별도의 작은 화면으로 구성한다.
- 날짜 렌더러: 스타일 옵션을 받아 빨간 스타일만 추가한다. 일반 내보내기의 기존 인자 기본값은 유지한다.
- 룩 설정 계산: 기존 프리셋을 직접 수정하지 않고 선택한 강도·질감에서 파생된 설정을 만든다. 미리보기/내보내기가 이를 같이 사용한다.

첫 장은 움직이는 `HTMLVideoElement` 참조가 아니라 셔터 시점 픽셀의 고정 복사본이어야 한다. 비동기 폰트/저장 처리 전에 이미지, 필터, 보정, 크롭, 미러 방향을 고정한다. 중간 두 장은 JPEG로 반복 인코딩하지 않으며 최종 결과만 JPEG로 인코딩한다.

새 합성 작업은 기본적으로 최종 긴 변 2048px 이하로 제한해 모바일 메모리를 줄인다. 입력보다 업스케일하지 않는다. 일반 촬영/이미지 편집의 기존 출력 해상도는 변경하지 않는다. 합성 안내에 이 출력 제한을 표시한다.

## 오류, 취소, 자원 해제

- 촬영/합성/출력 중 셔터 중복 입력을 차단한다. 타이머는 각 프레임에 적용하고 취소할 수 있다.
- 첫 장 실패는 대기로, 두 번째 장 실패는 첫 장을 유지한 두 번째 촬영 대기로 돌아간다. 저장 실패는 완성본을 유지하여 다시 시도할 수 있다.
- 완료 확인의 저장/공유 선택은 최근 촬영 보관의 기준이다. 공유를 취소해도 완성본과 로컬 사본은 남긴다. 보관하지 않고 취소하면 미완성 세션을 폐기한다.
- 첫 장이 있는 상태에서 모드 변경/이미지 편집 진입은 폐기 확인을 거친다. 카운트다운은 먼저 취소한다. 단순 앱 백그라운드 전환 시에는 메모리의 첫 장을 유지하되 새로고침/앱 종료 복구는 제공하지 않는다.
- 완성 확인/최근 사진 화면에서는 카메라와 미용 분석을 정지하고 돌아올 때 다시 시작한다. 지원되지 않는 장치/권한 오류는 기존 오류 표시를 유지한다.
- 교체/취소/삭제/화면 종료 시 ImageBitmap, 캔버스 참조와 object URL을 해제한다. 최종 사진 URL을 해제한 후 사용 중인 화면에서 참조하지 않도록 수명 주기를 분리한다.

## 검증 및 완료 조건

- 기존 타입 검사, 빌드, 33개 Playwright 테스트를 유지한다. 모든 촬영 비율의 실제 렌더 영역 중앙 정렬과 상단 안전 영역 회귀를 확인한다.
- 새 옵션을 선택하지 않은 고정 입력/고정 seed 결과가 기존 결과와 같은지 비교한다. 기존 사용자 LUT 데이터를 넣은 상태에서도 재실행 후 보존을 확인한다.
- 합성은 단색 입력으로 좌/우 순서, 크기/크롭, 혼합 0/50/100%, 날짜 한 번만 적용, 중간 이미지의 불변성을 검증한다.
- 첫/두 번째 촬영 실패, 재촬영, 모드 변경 확인, 타이머 취소, 중복 셔터, 완료본 재공유를 검증한다.
- 최근 사진은 재실행 후 조회, 10장/50 MiB 한도, 삭제, 공유 취소, IndexedDB 거부/쿼터 실패 시 기존 사진 보존과 공유 가능한 대체 흐름을 검증한다.
- 빨간 날짜는 네 촬영 비율 및 가로/세로/극단적으로 좁은 편집 이미지에서 프리뷰와 출력의 색상·크기·경계를 확인한다. 주황 기본 출력은 유지한다.
- 은은한 질감은 인물·밝은 실외·어두운 장면의 같은 사진에서 비교한다. “필름과 동일하다”는 정확도 주장은 하지 않는다.
- 실제 iOS 기기의 카메라, 백그라운드 복귀, 공유/다운로드, 저장소 사용은 자동 테스트로 보증할 수 없다. 사용자가 배포 후 실기기에서 확인할 항목으로 명시한다.
- 이 설계 승인과 구현 계획 승인 후 구현한다. 검증이 끝난 구현만 GitHub 반영/기존 Vercel 프로덕션 배포 대상으로 삼는다. 문서 작성만으로 배포하지 않는다.

## 이번 범위에서 제외

필터 목록/내비게이션 재설계, 사용자 계정/클라우드 사진첩, iOS 사진 라이브러리 전체 접근, RAW/네이티브 카메라 수준의 수동 제어, 세 장 이상 다중노출, 전체 필터 레시피 저장, 필터 출처/라이선스 변경, 블로그 수정은 포함하지 않는다.
